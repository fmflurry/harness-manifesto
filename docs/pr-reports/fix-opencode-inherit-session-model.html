harness-manifesto · fix/opencode-inherit-session-model

OpenCode uses the session model

The harness no longer names a model. Whatever you pick in OpenCode, or whatever your own OpenCode default is, is the model every agent runs.

1 · You choose

The session stores the model you selected. The harness does not set a top-level model.

→

2 · Primary agent

A primary agent with no model key uses that session model. conductor and Monolith main are both unset.

→

3 · Subagent

A subagent with no model key uses the model of the agent that invoked it. All 26 agents in opencode.jsonc are unset.

OpenCode documents this on opencode.ai/docs/agents: a subagent uses its configured model, or the parent session’s model when none is configured. Selecting a primary agent by id does not change the model the session already stored.

Before

Every agent had "model": "{env:OPENCODE_MODEL_*}". The installer wrote Mistral ids into the shell, so a fresh install ran Mistral even when you had chosen something else.

OPENCODE_REASONING_* was exported beside those pins. Nothing in opencode.jsonc read it.

After

The shell block only exports SETTINGS_OPENCODE_REPO. A reinstall rewrites the marker block, so the old exports disappear. bootstrap.ps1 clears the eight User-scope variables it used to set.

The myMistral provider block stays in the file. Nothing selects it unless you do.

Project install, two bugs fixed in the same installer

Hooks fired twice

A merge added bash ./.claude/hooks/kpi-emit.sh next to an existing bash "$CLAUDE_PROJECT_DIR/.claude/hooks/kpi-emit.sh".

The merge now keeps one command per event, matcher, and script, and writes the $CLAUDE_PROJECT_DIR form. A hook you wrote yourself, such as /opt/own/hook.sh, stays as you wrote it.

Copied scripts lost +x

rsync -a keeps the git mode. scripts/agent-harness/test/run.sh is checked in as 644, so the copy was not executable.

After the copy, any file whose first line is a shebang is marked executable. A file without a shebang stays as it was.

To pin one agent anyway

Set model on that agent in your own OpenCode config. This harness will not put the pin back on reinstall.

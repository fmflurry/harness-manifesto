Backups are cleaned up after a squash merge; worktree-rm works with Orca closed

0.4.40. Before: pre-rebase backups were never deleted (orbit had 22), and worktree-rm stopped whenever Orca's app was closed.

Backups (cleanup.sh)

PR merged→backups from goal file, else registry→ancestor of merge: delete→else: archive to refs/harness/backups/<name> (create only), then delete branch
  • goal backup-add mirrors into the registry, which outlives the worktree
  • An archive name already taken by another tip keeps the branch

worktree-rm with Orca closed (lib.sh, worktree-core.sh)

orca repo list fails with runtime_unavailable→offline→lsof sees this shell and no process in the worktree→git removes it
  • lsof missing or blind: stop
  • stderr warnings never break the stdout parse
  • Teardown of an Orca-created goal still stops

Tests

  • Suite in a clean env: 2405 passed / 75 failed; master 2388 / 75 (same failures)
  • New: archive, name taken, registry mirror, squash teardown, lsof blind stub, orca offline, stderr warning

Risks

  • lsof sees only the current user's processes and working directories
  • Backups made before this change have no registry entry and stay

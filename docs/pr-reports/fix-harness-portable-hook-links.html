Portable, git-ignored hook links

fix/harness-portable-hook-links · commit-provenance.mjs setup now writes relative links that stay out of project repos, and CI rejects any tracked absolute symlink.

Before

Absolute links got versioned

setup on machine A→ git-hooks/commit-msg → /Users/a/…/commit-provenance.mjs→ project repo commits it→ machine B: dangling link
  • The hook dir under a project's .claude/ or .opencode/ showed up as untracked and got committed.
  • On another machine the links pointed nowhere, so commits went through silently without the provenance hooks.
  • A re-run of setup hit an existing link and crashed with EEXIST.
After

Relative, self-ignored, guarded

setup (any machine)→ git-hooks/commit-msg → ../commit-provenance.mjs→ git-hooks/.gitignore = *→ resolves after copy / move
  • Links resolve wherever the install target is copied or moved.
  • The dir ignores itself, so project repos never see it.
  • Re-running is idempotent; stale links and stray files are replaced.

ARelative links

scripts/agent-harness/commit-provenance.mjs setup links each of the 28 git hooks to ../commit-provenance.mjs, computed from the realpath of the hooks dir (macOS /var → /private/var).

  • Correct link already there → skipped.
  • Stale symlink or regular file → removed and relinked.
  • A directory in a hook's place → refused (setup exits non-zero, contents kept).

BSelf-ignoring dir

git-hooks/.gitignore holds *. It is written with rmSync then writeFileSync(…, {flag:'wx'}), so a planted .gitignore symlink is removed, not written through.

CPortable-symlink guard

scripts/check-portable-symlinks.sh fails on any tracked symlink whose target is /… or C:/…, and fails when git ls-files fails. It runs in .github/workflows/portable-symlinks.yml (no path filter) and as the first step of npm test.

What changed

  1. The user-level hook writes unless .claude/settings.json also runs a different project kpi-emit.sh. A skip prints kpi-emit: skipped, project hook is registered.
  2. The same tool_use_id in one second is stored once, so user settings and project settings calling the same global script do not double the counts. A duplicate prints kpi-emit: skipped duplicate.
  3. OpenCode 2 data.location.directory is the session directory for later tools. The skill tool's id is the skill name. Token totals still use input plus output.
  4. A text report with no events now ends with coverage log missing or coverage empty selection. A collected report says n/a (no session total) or n/a (no duration_ms) when that one number was not sent.

The report still reads ~/.agent-harness/kpi/events.jsonl. It does not read opencode.db. Reinstall the harness so ~/.claude/hooks/kpi-emit.sh is this version. Events that were never written are not backfilled. The Metrics panel is this cloud session: the log was never created here, so that panel stays on log missing. The After card is the regression fixture, a real OpenCode session id, skill id, durations, and token total, recorded by the fixed user-level hook inside a checkout that vendors the script.

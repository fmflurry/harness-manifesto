ship-merge trusts local reviews when GitHub Actions is out of budget

feat(harness) · lib.sh pr_problems · ship-merge.sh · plugin 0.5.0

Decision path for a failed check

Failed check runon the PR head
→
Never started?app github-actions, job with no runner and no step, every failure annotation is GitHub's budget sentence
→
No real failure hidden?all runs of that check on the head: none ended failure or timed_out
→
Local proof?goal records passing code and security reviews of the exact head
→
Merge, loudlystderr warning, "Merged without CI" PR comment, ci_budget on the goal, KPI event

Any "no" keeps the old behaviour: the check counts as failing and ship-merge refuses.

Before

Out of budget → every job fails at once → ship-merge refuses → goal escalates → owner merges by hand, PR after PR.

After

Out of budget → refused jobs prove nothing → the locally verified, reviewed head merges → the PR says CI did not run.

Kept closed

  • a job that ran and printed the billing words (it has a runner and steps)
  • a test failure quoting the sentence (anchored match)
  • a real failure annotation beside the budget one
  • another app's check, or an API-made check with no job
  • a refused rerun over an earlier real failure
  • reviews of another head, or a failing review
